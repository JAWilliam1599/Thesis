\section{Chapter 1 --- Introduction} \hfill [p: 8-10]
\label{sec:intro}

\subsection{1.1 Background} \hfill [p: 2-3]
\begin{itemize}
    \item Growth of cloud computing in recent years.
    \item Multi-cloud and hybrid-cloud adoption in large enterprises; drivers
          (data residency, legacy on-prem systems, cost, resilience).
    \item Security challenges specific to the hybrid model (split trust boundary,
          heterogeneous control planes).
    \item The shift-left / DevSecOps trend and the rise of AI-assisted code generation.
\end{itemize}

\subsection{1.2 Research Challenges in Hybrid Cloud} \hfill [p: 1-2]
\begin{itemize}
    \item Weak security linkage between public and private cloud.
    \item Absence of a clear, repeatable security process across the two sides.
    \item Fragmented, disconnected security tooling with inconsistent outputs.
    \item Misconfiguration risk amplified by fast, AI-generated IaC.
\end{itemize}

\subsection{1.3 Research Gaps} \hfill [p: 1]
\begin{itemize}
    \item Few papers propose or build an end-to-end security \emph{process} for hybrid cloud.
    \item Tool integration is hard; findings from different tools need a unified,
          quantitative score rather than isolated pass/fail signals.
    \item Deployment context (exposure, cost) is rarely folded into prioritization.
\end{itemize}

\subsection{1.4 Research Objectives} \hfill [p: 1]
\begin{itemize}
    \item O1: Propose a pipeline that links security across public and private sides
          of a hybrid cloud.
    \item O2: Propose a risk-scoring method that aggregates heterogeneous tool findings.
    \item O3: Build a reference system implementing the pipeline.
    \item O4: Evaluate the reference system across 2 scenarios.
\end{itemize}

\subsection{1.5 Contributions} \hfill [p: 1]
\begin{itemize}
    \item C1: A reusable SysSecOps \emph{pipeline/architecture} with a security gate
          placed between IaC synthesis and deployment, applied uniformly to both the
          AWS (CDK) and on-prem (Ansible) sides.
    \item C2: A reference \emph{system} implementing the pipeline (AI generation +
          regen feedback loop, multi-scanner gate, risk scoring, deploy governance,
          Phase 4 monitoring, CLI + Streamlit UI).
    \item C3: A quantitative, deduplicated, ML-augmented \emph{risk-scoring engine}.
    \item C4: A \emph{systematic evaluation} over 2 scenarios (correctness, scoring
          behavior, deployment, and observability).
\end{itemize}

\subsection{1.6 Thesis Structure} \hfill [p: 0.5]
\begin{itemize}
    \item One paragraph mapping each remaining chapter.
\end{itemize}
